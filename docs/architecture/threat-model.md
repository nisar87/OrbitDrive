# Threat model (phase 0 baseline; revisit each phase)

| # | Threat | Component | Current mitigation | Status / gap |
|---|---|---|---|---|
| T1 | Stolen account token used from attacker's browser | Gateway | Account token alone grants nothing; needs approved browser-device credential | Tested. Device secret is a bearer secret in localStorage — XSS on the web origin would expose it (CSP is W11; platform-key design is W1) |
| T2 | Attacker shows victim a QR for the attacker's PC, or relays a victim PC's QR | Pairing | Claim binds account+request; PC shows account, browser name and 6-digit code; owner must approve locally; PC already owned cannot be claimed by another account | Tested. QR is not proof of proximity — stated in UI copy plan |
| T3 | Pairing code guessing / replay / race | Gateway | 10-char secret from 31-symbol alphabet, hashed; 5 failed attempts burn the request; 2-minute TTL checked at claim and confirm; atomic one-use claim; new request supersedes old | Tested (incl. 64-way race). Claims are also limited to 10/min per client address and per account, polls to 90/min per account (429 + Retry-After); the client address comes from X-Forwarded-For only when the TCP peer is a configured trusted proxy, right-most entry only (tested with forged headers). Limits are in memory on the single relay instance |
| T4 | Cross-account / cross-PC access | Gateway | Owner + device grant checked on every route; foreign PC returns 404 | Tested |
| T5 | Path traversal, absolute/UNC/device paths, ADS, reserved names | Core | Sealed IDs + per-segment validation even for genuinely sealed tokens | Tested on Windows and Linux |
| T6 | Symlink/junction/ancestor-swap redirect | Core | Reparse refusal per component + opened-handle final-path check; served from same handle | Tested incl. ancestor swap. Volume-identity binding of roots is D4. **2026-11-17:** listings validated the path and then enumerated it by name again; a live swap test on Windows showed an outside folder's names could leak. Listings now enumerate through the validated, pinned handle; race test passes on Windows and Linux |
| T7 | Hard link exposing a file outside the root | Core | Windows link count > 1 refused | Tested on Windows. Not enforced on non-Windows dev hosts. Windows test creates a real second link to an outside file and proves refusal |
| T8 | Resume splicing two file versions | Core/Gateway | Content-hash ETag; If-Range mismatch → full body; agent revalidates size+mtime per range | Tested. Timestamp-restoring same-size rewrite is a known gap (D5) |
| T9 | Download capability leak (logs, Referer, history) | Gateway/Web | Hashed at rest; request-path logging off; `Referrer-Policy: no-referrer`; `no-store`; expiry; revocation cancels live streams | Tested for logs/revocation/expiry. Capability is bearer: whoever has the URL can download until expiry |
| T10 | Malicious/compromised gateway instructs agent | Agent | Closed action set; local root policy; pause; only reads approved roots | A compromised relay can still read files in approved roots while the agent runs — inherent until E2EE (E-D3) |
| T11 | Rogue agent impersonates a PC | Gateway | pcId is the key hash; nonce signature; older connection generation cut off | Tested |
| T12 | Browser-origin WebSocket to agent channel | Gateway | Requests with an `Origin` header are refused | Tested |
| T13 | Memory/connection exhaustion | Gateway/Agent | 64 KiB JSON body cap, 256 KiB control message cap, per-owner stream cap (4), agent stream cap (4), pending-request caps | Partly tested. No global rate limiting/quotas yet (W10) |
| T14 | Local malware as the same Windows user | Agent | DPAPI CurrentUser for keys | Not a defence against same-user malware (stated limitation) |
| T15 | Dev identity reaching production | Gateway/Web | Gateway refuses to start in Production; web production build guard | Tested |
| T16 | Operator visibility | Relay | No payload logging or storage | Operator with relay access can observe traffic; disclosed |
| T17 | Hostile filenames (XSS, RTL, control chars) | Web | React text rendering only; `bdi` isolation; names with control chars are never listed | Preview-related risks are W7 |
| T18 | A different disk appears at an approved path (another USB stick on the same drive letter) | Core | Each root records the volume identity it was approved on; listing, preparing and already-prepared downloads are refused as unavailable on mismatch; never re-bound automatically | Tested with real volume serials and a simulated swap; no physical removable-disk swap evidence |
| T19 | Hostile image (decompression bomb, truncated/corrupt data, malformed headers, EXIF tricks) | Agent / helper | Header probe refuses oversize before decoding; separate helper process with timeout, output cap, memory-limited job object (Windows), failures are never described to the browser; failure memo avoids retry storms | Tested: bomb/corrupt/truncated corpus against the real decoder on Linux and Windows CI. Job-object limits are asserted only by the helper-start/kill behaviour, not by an adversarial memory test. No fuzzing |
| T20 | Content that looks like an image/text but is active (HTML named .png, SVG, script in text) | Gateway / Web | Allow-list from sniffed bytes; second allow-list in the gateway; CSP `default-src 'none'; sandbox` + `nosniff`; text rendered as characters; SVG never inline | Tested (Core, integration, Playwright on 5 browser projects: `window.__xss` stays undefined) |
| T21 | Preview used to bypass revocation or source change | Core / Gateway | Preview read tokens and derived thumbnail tokens re-validate root, volume and source revision on every read; revoked device gets 401/403 | Tested (integration + e2e) |
| T22 | Hostile PDF | Web | pdf.js with scripting, forms, annotation and text layers off; 64 MiB / 2000-page caps; no links or embeds rendered; damaged files fall back to Download | Partly mitigated: the renderer runs in the page origin. **Open:** iframe/sandbox origin isolation. Malformed-PDF corpus is two files |
| T23 | Staged archive leaks data or exhausts the PC (other user's selection, huge tree, disk fill, leftover files) | Agent | Archive ids and read tokens are sealed and bound to PC, device and root; walk uses the browsing access check; hard limits and a free-space reserve; jobs dropped on root removal/revocation and after 6 h; crash cleanup at start | Tests: ArchiveTests (limits, omissions, rollback, cleanup), archives.test.mjs (foreign device/PC refused, extract-and-compare) |
| T24 | Search reveals names outside the caller's scope or across users/PCs | Agent / Gateway | Same access path as browsing; PC-scoped routes; unshared root stops mid-search; unavailable roots named, not searched | Tests: SearchTests, search.test.mjs (revoked, foreign, partial) |
| T25 | Entry-check / favorites used to probe other PCs or learn about removed items | Core / Gateway | ≤ 100 ids per call; ids unsealed only for the PC they were issued for; unavailable items return no data | Tests: entry-check cases in search.test.mjs; library.test.ts (ids only sent to their own PC) |
| T26 | One browser device across PCs widens revocation or cross-PC authority | Gateway | Claim reuses the device only for the signed-in owner; grants stay per PC; PC-side revoke is PC-scoped | Tests: GatewayTests device-reuse (3), multipc.test.mjs (3) |
| T27 | Upload writes outside the enabled folder (traversal, forged or cross-root folder ids, symlink/junction swap, reserved names) | Core | Folder id unsealed only for that PC and root; final folder re-pinned (`PinFolder`) inside the root and same disk; segment/name/length rules; partial folder is a reserved name hidden from listings | Tests: UploadTests (incl. symlink swap, cross-root), uploads.test.mjs forged ids. **Residual:** local-attacker race between pin and move |
| T28 | Upload into a read-only root, or after the owner turned uploads off | Core / Agent | Every call re-checks `UploadsEnabled`; turning off or removing a root drops its sessions and partials | Tests: UploadTests, uploads.test.mjs (off mid-upload), upload.spec.mjs |
| T29 | Disk, quota or concurrency exhaustion by an uploader | Core / Gateway | Per-file limit, quota (used + in-flight reserved), 512 MiB free-space reserve, 3 active uploads (global and per device), idle TTL 45 min, lifetime 12 h, request throttles | Tests: Core limits/expiry (hooks), uploads.test.mjs 507 and cap. **Not tested:** real 45-minute expiry; mid-chunk disk-full only via hook |
| T30 | Revoked or other device continues or reads an upload | Gateway / Agent | Gateway stamps the device id; sessions visible only to the creating device (others get 404); revoke cancels that device's uploads and deletes partials | Tests: uploads.test.mjs (revocation both ways, ownership) |
| T31 | Partial or damaged file appears as a real file; overwrite by race | Core | Data only in the private partial folder; commit by no-replace move; checksum per piece and whole-file hash on finish; cancel/crash cleanup | Tests: UploadTests (crash cleanup), uploads.test.mjs (mismatch, cut-off piece, crash recovery, collisions) |
| T32 | A user reaches operator functions (self-promotion, hidden route, stale or replayed sign-in) | Gateway | Operator list from deployment config only; checked on every admin call; sign-in must be recent; per-operator throttle | Tests: admin.test.mjs (users/strangers/anonymous 403/401 on every endpoint, stale 401, no operators = no admin), admin.spec.mjs (no admin chunk fetched for ordinary accounts) |
| T33 | Operator abuse or over-reach (reading files, impersonating, silent actions) | Gateway | No file/path/impersonation endpoint exists; only ids and counts are shown; every action needs a reason and is written to an append-only audit file naming the operator | Tests: admin.test.mjs (no browse routes; overview/users leak nothing; audit entries). **Residual:** an operator with host access can read the relay's memory and TLS-terminated traffic |
| T34 | Suspended or revoked account keeps working | Gateway | Authorize and pairing check suspension on every call; suspension and revoke-all cancel live downloads and uploads; suspension persists across restart | Tests: admin.test.mjs (403 on every path, restart, unsuspend) |
| T35 | Account deletion leaves access or deletes user data on a PC | Gateway | Devices removed, PCs released, prefs erased; no gateway code path deletes or writes PC files; requires recent sign-in and exact phrase | Tests: admin.test.mjs and admin.spec.mjs (files byte-identical afterwards, registrations.json has no trace, audit has the deletion). **Residual:** backups of the data directory |
| T36 | Relay-byte exhaustion by one account | Gateway | Optional per-account UTC-day relay cap checked before each download stream and upload piece; operator can restore it | Tests: MetricsTests (midnight rollover), admin.test.mjs (refusal and restore). A transfer already running may pass the cap |
| T37 | Forged, replayed, downgraded, swapped-host or tampered update | Core | See ADR-23 | Tests: UpdateTests (signature, key, expiry, version, rollback, channel, protocol, URL/host/name/hash/size cases, tampered or interrupted file, crash recovery, cross-language fixture). **Not tested:** real installer, real signing key |
